## 実施内容

### スケジュール再設計

15分スロット単位の貪欲法で詰め直した。制約は「同一コートで時間帯が重ならない」「同一チームの試合間隔15分以上」の2点。

```
グループ戦   09:00 〜 15:45   (27スロット × 15分、80試合)
Round of 16  16:03 / 16:21 / 16:39
Quarter      17:15 / 17:33
Semi         18:09
Final        18:45 〜 19:03
```

- 終了 **19:03**（従来比 5時間以上短縮）
- コート重複 **0件**、休憩違反 **0件**
- コート稼働率 **98.8%** — 80試合 ÷ 3コート = 27スロットが理論下限なので、これ以上は詰められない
- コート分散 C1=34 / C2=32 / C3=29

### 保存先の移行

ブラウザーの JavaScript はローカルファイルへ書き込めないため、Vite 開発サーバーに API ミドルウェアを組み込んだ。ランタイム依存の追加はゼロ。

| | 変更前 | 変更後 |
|---|---|---|
| 保存先 | localStorage | `TempServerData/matches.json` |
| 同期範囲 | 同一ブラウザーの別タブのみ | 全端末（SSE 即時配信） |
| 同期方式 | 30秒ポーリング + storage イベント | SSE |

- API 5本: `GET /api/state` / `GET /api/stream` / `PATCH /api/matches/:id` / `PUT /api/matches` / `POST /api/reset`
- 書き込みは Promise チェーンで直列化、一時ファイル + `rename` でアトミック保存
- ファイル破損時は `matches.corrupt-<日時>.json` へ退避して再生成
- エラー応答は `code`（`UNKNOWN_MATCH` / `FIELD_NOT_PATCHABLE` / `INVALID_FIELD_VALUE`）を持つ

管理者ログイン状態（`cupflow-admin-authed`）は localStorage に残した。端末ごとの状態であり、サーバーに置くと1人のログインで全端末が管理者になるため。

### 初期データとリセット

全95試合を `SCHEDULED`・スコア0・タイマーなしで生成する。ノックアウト15枠も時刻・コート付きで最初から用意し、対戦相手のみ `TBD` とした。

管理画面に `↺ Reset all matches` を追加。従来はブラウザーの localStorage を手で消す必要があった。`window.confirm` は画面全体をブロックするモーダルなので使わず、2段階クリック方式にしている。

## 検証で見つかった重大な問題

### リアルタイム同期が実ブラウザーで完全に動いていなかった

**35件のテストが全て緑の状態で埋まっていた。**

SSE の仕様では複数行ペイロードの全行に `data: ` が必要だが、実装は `JSON.stringify(state, null, 2)` と整形出力していた。仕様どおりパースすると `event.data` は `"{"` だけになり、`JSON.parse` が例外を投げる。

原因は、SSE のテストが**生バイトの部分文字列**を見ていたこと。

```ts
expect(pushed).toContain('"homeScore": 7');   // 生バイトには含まれるので通る
```

修正では単一行 JSON に変えるだけでなく、**テストを「仕様どおりフレームをパースして `JSON.parse` する」形に差し替えた**。整形出力に戻すとテストが落ちることも確認済み。

### その他

| 問題 | 内容 |
|---|---|
| 開発サーバーが落ちる | SSE で `writeHead` 後に読み取り失敗すると二重 `writeHead` → 未処理の Promise 拒否 → **プロセスごと終了** |
| データ消失の危険 | `load()` が `error.code` を見ず、一時的なファイルロックを「ファイル無し」と誤認して**進行中の大会データを空で上書き** |
| 購読・タイマーの漏れ | SSE のクリーンアップ登録が `await` の後にあり、待機中の切断でリスナーとタイマーが永久に残る |
| 編集の消失 | 他の管理者が**無関係な試合**を更新すると、入力途中のスコアが黙って巻き戻る |
| 順位表が NaN | PATCH がフィールド名しか検証せず、`{"homeScore":"banana"}` が 200 で保存される |
| Live 画面が無意味 | `Map` が重複キーで最後を残すため、コートごとに「最も遅い」試合を表示。全95試合が最初から `SCHEDULED` になった結果、一日中 `FINAL-1` / `SF-2` / `QF-3` が TBD 表示 |
