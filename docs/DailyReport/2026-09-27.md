## Vercel 移行

元のアプリは Cloudflare Worker + SQLite Durable Object + WebSocket を前提としていた。Vercel では Durable Object を動かせないため、以下の構成を追加した。

- Vite の Cloudflare プラグインを本番ビルドから外し、静的 SPA として `dist` を配信。
- `/api/*` を Vercel Functions として実装。
- Neon の公式 `@neondatabase/serverless` ドライバーを使用し、共有状態とログイン試行を Postgres に保存。
- Vercel Functions に WebSocket の常時接続を置かず、クライアントから2秒ごとに `/api/state` を取得。
- Cloudflare の Worker 構成は残し、Vercel 用の実行経路を追加。

## デプロイ後に発生した問題と対応

### Neon 接続で API が失敗

独自実装が SQL endpoint を固定していたため、Neon 公式 serverless driver に置き換えた。

### `/api/_shared` の module not found

Vercel の Node ESM で拡張子なし import が解決されなかった。共有 API 処理を `lib/vercel-api.ts` に移し、API handler と大会初期データへの実行時 import を `.js` 拡張子付きにした。

### Vercel が `Response` を無視

Runtime Logs に `default export returned a Response` の警告が出た。Vercel が default export を `(req, res)` 形式として扱っていたため、各関数を名前付き `GET`、`POST`、`PUT`、`PATCH` export に変更した。

### 試合操作の PATCH が 405

`/api/matches/G-A-1` が動的 route `/api/matches/[id]` に届いていなかった。`vercel.json` に次の rewrite を追加した。

```json
{ "source": "/api/matches/:id", "destination": "/api/matches/[id]" }
```

## 環境変数

Vercel の **Settings → Environment Variables** に以下を設定する。Preview を使う場合は Preview にも登録し、値を変更したら該当環境を再デプロイする。

- `DATABASE_URL`: Neon の Postgres 接続文字列
- `SUPERADMIN_PASSWORD`: `superadmin` のパスワード
- `SUBADMIN_PASSWORD`: `subadmin1`〜`subadmin6` 共通パスワード
- `SESSION_SECRET`: セッション署名用のランダムな秘密文字列

秘密値は日報や Git に記録しない。`superadmin1234` はローカル開発例であり、本番・Preview の初期値ではない。
