## 段階0: Cloudflare への移行

前日までの構成（Vite 開発サーバーのミドルウェアと `TempServerData/matches.json`）は、`npm run build` の成果物にサーバーが含まれない。そのためデプロイすると保存・同期がすべて動かなかった。

| | 変更前 | 変更後 |
|---|---|---|
| 実行環境 | Vite 開発サーバー | Cloudflare Workers（静的アセット + `/api/*`） |
| 保存先 | `TempServerData/matches.json` | Durable Object `TournamentRoom` の SQLite |
| 同期方式 | SSE | WebSocket（Hibernation API、`ping`/`pong` で死活確認） |
| 開発時 | `npm run dev` | `npm run dev`（`@cloudflare/vite-plugin` で workerd 上に Worker を起動） |

- Durable Object は1インスタンス（名前 `main`）で、すべての変更を直列に処理する。
- 試合データはメモリに持たず、常に SQLite から読む。休止・退避から戻っても内容が残ることをテストで確認した。
- クライアントは切断されると、1秒から最大10秒まで間隔を延ばしながら再接続する。25秒間何も届かない接続は張り直す。
- 2つの WebSocket クライアントを開発サーバーに接続し、片方の得点変更が両方に約0.5秒で届くことを確認した。

## 段階1: 認証

前日までは、パスワード `VELOCITY-DEMO-ONLY` がクライアントのコードに埋め込まれていた。localStorage に `"true"` を書くだけで管理者になれ、API も無認証だった。

| | 変更前 | 変更後 |
|---|---|---|
| アカウント | 管理者1種類 | `superadmin`（全コート）、`subadmin1`〜`6`（2人ずつ Court 1〜3） |
| パスワード | クライアントのコードに埋め込み | Cloudflare の Secrets（`SUPERADMIN_PASSWORD`・`SUBADMIN_PASSWORD`） |
| ログイン状態 | localStorage | サーバーが署名した `session` Cookie（HttpOnly・Secure・SameSite=Strict・12時間） |
| API | 誰でも変更可 | 未ログイン `401`、権限なし `403`、担当外コート `403 WRONG_COURT` |
| 画面 | `/admin/setup` | `/superadmin`・`/subadmin`（旧 URL は転送） |

- **試行制限:** 同じユーザー名で5回続けて失敗すると、60秒間 `429` を返す。並行して10回送っても、失敗として受け付けるのは5回だけであることをテストで確認した。
- **偽装対策:** Worker は外から来た `x-auth-*` ヘッダーを必ず消し、検証済みの利用者だけを Durable Object に渡す。
- **CSRF 対策:** 変更系の API は `content-type: application/json` を必須にした（違えば `415`）。
- **設定漏れの対策:** Secret が未設定なら、ログインは `AUTH_NOT_CONFIGURED` で拒否する。空のパスワードや空の署名鍵では通らない。
- **確認:** ブラウザーに配信するコード（`dist/client`）にパスワードが含まれないことを確認した。

進め方は、タスクごとに別のエージェントが実装し、別のレビュー担当が確認する方式にした。5タスクすべてで Critical・Important の指摘は無かった。ブランチ全体の最終レビューでもセキュリティ上の不具合は見つからなかった。

## 見つかった問題

### 仕様書の §1〜§9 が文字化けしていた

段階0の最終コミット（`0e06320`）で、`docs/仕様書.md` の §1〜§9 が読めなくなっていた。UTF-8 の文字を Shift-JIS として読み直し、そのまま保存されたためである。このコミットは push 済みだった。

変更前の版（`b469182`）と比べて中身に変更が無いことを確かめ、§1〜§9 をその版から復元した（`886b88f`）。§1・§2 に残っていた `TempServerData` の説明も Cloudflare の構成に書き換えた。以後、仕様書の編集後は文字化けの有無を検査している。

### ログアウトに失敗しても、ログアウトしたように見えていた

最終レビューで Important として指摘された。会場の通信が途切れて `POST /api/logout` が失敗しても、画面は「ログアウト済み」になっていた。実際には Cookie が最大12時間有効なままで、再読み込みすると管理画面に戻る。スタッフ間で端末を渡すと、次の人が権限を持ってしまう。

失敗したときはログイン状態のまま「Could not sign out」と表示するように直した（`1890070`）。
